# trust-surface.txt -- every site in verus/src that Verus does not prove.
#
# The counterpart of the SPARK crate's spark/scripts/trust-surface.txt.
# One entry per site, checked by scripts/check-trust-surface.sh:
#
#     kind | path | entity | why no Verus formulation works
#
# Paths are relative to verus/. `entity` is `-` for the file-level kind
# (foreign-binding). The fourth field is required, and it is what a reviewer
# reads. The kinds, and what is not counted (Verus, Z3, rustc, and vstd's
# specifications of std), are in the script's header.
#
# The crate is meant to have no assumptions, as the SPARK crate. The only
# entries are the FFI exports to Cryptol (src/ffi/, outside verus! because
# they take Cryptol's raw pointers), as the SPARK crate's only entries
# besides its proof justifications are its foreign-binding FFI units. Any
# other entry is a hole: it is reported as one in the change that adds it.
#
# Everything else in verus/src is inside verus! and verified, with no
# assume, admit, axiom or external body, and it calls no unverified
# function of vstd. (Slicing by a range is std's indexing, &M[i..j], whose
# specification vstd gives as for M[i]; vstd::slice::slice_subrange, an
# external_body wrapper of the same, is not used.)
#
# The exports are tested, not proved: scripts/check-ffi.sh runs every
# property of cryptol/properties.txt through them. Each export only reads
# Cryptol's arguments, checks at run time the preconditions of the proved
# function it calls that Cryptol's types are meant to ensure, calls it, and
# writes the result; its one loop (the incremental HMAC) is
# src/ffi/hmac_sha256.rs's hmac_chunked, inside verus! and proved.
#
