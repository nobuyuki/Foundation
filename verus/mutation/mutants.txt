# mutants.txt -- the mutants of the executable Verus code, read by
# scripts/mutation.py. The counterpart of the SPARK crate's
# spark/mutation/mutants.txt (github.com/manthonyaiello/Foundation, tag
# spark-v1.0): the same 84 faults, under the same ids, each written on the
# Verus source that does what the SPARK line does.
#
# Each mutant is one small change to one line of one source, in the
# executable code (never a contract, an assertion, a proof block or a spec
# function), with one kind of exception, the F*b mutants below: an operator,
# a constant, an off-by-one bound, a loop bound, an index, a dropped
# statement or a swapped call. The script copies the checkout to a scratch
# tree, applies one mutant at a time there, and never writes a mutant into
# this checkout.
#
# Mutant lines:
#
#     id | file | line | from | to | ffi | prove | what
#
# id     A (AES.Impl: aes/aes_impl.rs), M (AES.Impl.Main:
#        aes/aes_impl/main.rs), S (SHA2.SHA256_Stream: sha2/sha256_stream.rs),
#        H (HMAC.SHA256_Impl: hmac/sha256_impl.rs), F (SHA2.Functions:
#        sha2/functions.rs), and the SPARK crate's number.
# file   The source, relative to verus/.
# line   The line the change is on, in the source at the commit that adds
#        this list; `mutation.py check` fails if from is not on it, once.
# from   The text replaced, which must occur exactly once on that line.
# to     Its replacement (`{}`, an empty block, for a dropped statement:
#        the SPARK list's `null;`).
# ffi    The FFI properties run for the mutant: group names (below) and
#        property names, space-separated, in the order they are run. A
#        survivor of these is then run against every property
#        (`mutation.py ffi --full`).
# prove  The modules Verus verifies for the mutant (`cargo verus focus --
#        --verify-only-module M ...`), or a group: the mutated module, the
#        counterpart of the SPARK list's units for gnatprove -u.
# what   What the change is, in words.
#
# A mutant of more than one line has one line per change, under the same id,
# each with the same ffi, prove and what; they are applied together.
#
# Group lines:  group NAME = MEMBER ...   (a member may be another group,
# by its name).
#
# How the list differs from the SPARK crate's:
#
# * F01 to F07 come in two kinds. In the SPARK crate SHA2.Functions is one
#   set of expression functions, which the spec layer and the implementation
#   share, so a mutant there changes both, and gnatprove proves the
#   implementation against the mutated spec. Here the spec functions and
#   their executable twins (the `exec` submodule) are separate code:
#     F01a ... F07a  change the executable twin alone (the rule above);
#     F01b ... F07b  make the same change to the spec function and to its
#                    twin, two lines: the SPARK mutant's effect (spec and
#                    implementation agree, and both are wrong).
# * S27, S28 and S29 are not here (their ids are unused): each slices an
#   array from 0 instead of from its 'First, a fault Rust cannot have (every
#   slice starts at 0).
# * A29 cannot drop the initialization (Rust requires it): it changes the
#   initial value, which is equally dead (every word is written before it
#   is read).
# * Where the SPARK code has one statement per byte and this code a loop
#   (Final's length bytes, S21 to S25), the change is made to one iteration
#   of the loop by a condition on its index, so that it is the same fault.
# * The FFI groups name the properties that reach the mutated function,
#   which include this crate's exports of the leaf functions (prop_xTimes,
#   prop_SBox, prop_SubBytes, ...): doc/ffi.md.
